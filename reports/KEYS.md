# Ключи карт в СКУД Gate — как это устроено

> Обновлено: 2026-11-18 17:05 (Europe/Kaliningrad).
> Относится к приложению `reports/` — мониторинг и отчёты, порт 8110 на LXC `192.168.2.193`.
> Общая документация приложения — `README.md`, состояние проекта — `../STATE.md`.

## СРОЧНО, до начала работы

**GateTerm на сервере Gate стоит на окне «Регистрация оператора».** Пока в него
не войдут:

- **двери из приложения не открываются** — мост ищет окно «Управление точками
  доступа», а его нет, пока оператор не вошёл;
- картотеку и передачу ключей автоматизировать нельзя.

Войти: имя оператора и пароль. Операторы лежат в таблице `Operators` в
`config.mdb` (поля `Name`, `Password`, `Users`, `Admin`): `Admin`, `ok`, `hr`,
`smtv`, `senv`, `sbz`, `tehdir`, `make`, `svk`. Право `Users` — доступ к
картотеке, `Admin` — полные права.

Причина, по которой сессия сбросилась: в VB-диалоге ошибки была нажата кнопка
«ОК», а она **завершает GateTerm**. Сторож (`bridge_watchdog.bat`) поднял
приложение заново, но вход оператора пришлось делать с нуля.

## Что работает, а что нет

| Операция | Состояние |
|---|---|
| Выдать пропуск (новый человек) | **работает** — карта открывает двери, проход в журнале с именем |
| Отозвать / удалить пропуск | **не работает** — запись из базы уходит, а ключ в контроллере остаётся |
| Истечение срока | **не работает** по той же причине |
| Открыть дверь из приложения | работает, если GateTerm залогинен |

**Практическое следствие:** карта, однажды заведённая, открывает двери, пока её
не уберёт сам Gate. Единственная надёжная защита — забирать карту у посетителя
физически.

## Как выдаётся ключ (эта часть работает)

```
Пропуска → «Выдать пропуск» (карта + двери)
   → приложение пишет SQL-задание в очередь C:\GATE\_skud_queue\
   → приложение кладёт туда же zz_gateserv_restart.cmd
   → агент на сервере Gate (раз в 2 минуты) выполняет SQL в config.mdb
   → и сразу перезапускает GateServ
   → GateServ при старте читает картотеку и пишет ключи в свободные слоты
   → карта открывает двери; проход в журнале — с ФИО
```

Задержка от выдачи до работающей карты — до 2–3 минут.

### Три вещи, без которых выдача не работала

1. **Перезапуск GateServ.** Запись в `config.mdb` сама дверь не открывает:
   служба читает картотеку при старте. Отсюда важное — состояние
   `gate_state = ok` означает «SQL выполнился», а не «дверь знает карту».
2. **Слот ключа — один на устройство.** `AccessTable.InnerNum` должен совпадать
   у считывателей одного устройства и быть свободным на устройстве: память
   ключей у контроллера общая. Если выделять слот каждому считывателю отдельно,
   ключ встаёт в занятый слот и контроллер отвечает «Нет доступа. Неразрешенный
   ключ». Проверено на данных: у 74 из 83 сотрудников, у кого есть оба
   считывателя одного устройства, слот одинаковый.
3. **Срок действия в Gate не выставляем** (`UseExpiry = 0`): у всех 288
   сотрудников он пуст, а пользователя с заполненным сроком Gate не сопоставляет
   с событием — проход в журнале остаётся без имени.

**Строки доступа пишутся только на «считывателе доступа»** — том, где уже есть
картотека (обычно `Readers.Num = 1`). Исключение — «Вход из Зала»: там оба
считывателя рабочие, и человек получает на них один и тот же слот, как делает
сам Gate.

## Почему отзыв не работает

**Служба GateServ при старте пишет ключи только в свободные слоты.** Отсюда всё
сходится:

| Действие | Слот в контроллере | Результат |
|---|---|---|
| Добавили нового человека | был свободен | ключ записался |
| Сменили карту у существующего | занят старым ключом | не перезаписался |
| Удалили запись | занят «осиротевшим» ключом | не очистился |
| Заблокировали (`Status = 1`) | занят | не передалось |

Ключ, попав в контроллер, остаётся там навсегда — своими силами его оттуда не
вынуть.

### Что проверено и не помогло

| Способ | Результат |
|---|---|
| Удалить запись из `Users` + перезапуск | ключ остался, карта пускает |
| Пометить `Status = 1` (как заблокированные сотрудники) | ключ остался |
| Подменить значение карты в том же слоте + перезапуск | ключ остался |
| Команда меню Gate «Передача ключей в контроллеры» (id=41) | ключ остался |

Проверка всегда одна и та же: **приложить карту к двери**. По базе проверять
нельзя — там запись уже удалена, а дверь всё равно открывается.

Подтверждение из журнала Gate: проходы **без имени** на том считывателе, где
ходила удалённая карта (контроллер пускает, а Gate карту уже не знает).

## Что известно про интерфейс Gate (меню GateTerm)

Получено разведкой (`GateUi.exe`, см. «Инструменты»). Меню главного окна:

```
[0] Конфигурация      id=2 Точки подключения, id=3 Контроллеры, id=9 Расписания,
                      id=26 Операторы …
[1] Бюро пропусков    id=28 Пользователи ← картотека, id=29 Группы,
                      id=31 Доступ для групп, id=34 Печать пропусков …
[2] Прием-передача    id=40 Передача настроек в контроллеры,
                      id=41 Передача ключей в контроллеры,
                      id=42 Очистка банков ключей контроллеров
```

Пункт меню нажимается так: `PostMessage(mainWnd, WM_COMMAND /*0x0111*/, id, 0)`.
Главное окно — класса `ThunderRT6FormDC` с заголовком `GATE Terminal. Версия …`.

Окно «Передача ключей в контроллеры» (открывается по id=41): `id=7` флажок
«Выбрать все», `id=8` список точек, `id=5` кнопка «Выполнить», `id=9` «Выход».

### Грабли интерфейса Gate

1. **Окна модальные, по одному.** Пока открыто одно окно, открыть второе нельзя:
   Gate показывает `Run-time error '400': Form already displayed; can't show
   modally`.
2. **«ОК» в VB-диалоге ошибки завершает GateTerm.** Не нажимать. Если диалог
   появился — лучше подождать сторожа, который поднимет приложение, чем жать ОК.
3. **После перезапуска нужен вход оператора** — автоматизация без пароля
   встанет.
4. Управляющие элементы — класса `ThunderRT6*` (VB6). Нажатие: `SendMessage(h,
   BM_CLICK /*0x00F5*/, 0, 0)`, флажок: `BM_SETCHECK /*0x00F1*/` со значением 1.

## Рекомендованный путь (следующий шаг)

**Снять команду, которой Gate чистит слот.** Инструмент мониторинга очереди
команд готов и проверен (`GateQMon.exe`, ловит `CommandQuetch` в реальном
времени).

Порядок:

1. Войти в GateTerm оператором.
2. Включить монитор очереди команд на 2–3 минуты.
3. Удалить одного тестового человека **через картотеку Gate** (меню
   «Бюро пропусков» → «Пользователи», id=28).
4. В дампе монитора увидеть точную команду, которой Gate чистит слот.
5. Повторить её из приложения — после этого отзыв и удаление заработают.

Альтернатива — полная автоматизация картотеки Gate (открыть id=28, найти
человека, нажать «Удалить»). Путь дороже и хрупче: модальные окна, обязательный
вход оператора, риск уронить приложение на ошибке.

Ещё вариант — меню id=42 «Очистка банков ключей контроллеров»: она стирает
память ключей целиком, после чего id=41 заливает их из базы заново. Это убрало
бы «осиротевшие» ключи, но на время операции двери не пускают — в рабочее время
делать нельзя.

## Инструменты на сервере Gate

Собраны из исходников в `bridge/`, лежат в `C:\Users\Public\`. Запускаются через
очередь (`*.cmd` + пустой `*.sql`, чтобы сторож разбудил агента) или напрямую
через `PsExec64.exe -i 1 -s` (в интерактивном сеансе).

| Инструмент | Что делает | Куда пишет |
|---|---|---|
| `GateUi.exe` | выписывает все окна GateTerm, их элементы и меню | `gate_ui.txt` |
| `GateMenu.exe <id>` | нажимает пункт меню по id | `gate_menu.txt` |
| `GateKeys.exe [сек]` | открывает «Передача ключей», ставит «Выбрать все», жмёт «Выполнить» | `gate_keys.txt` |
| `GateClean.exe` | закрывает модальные окна (диалог ошибки и окно передачи ключей) | `gate_clean.txt` |
| `GateQMon.exe <сек> <файл>` | мониторит таблицу `CommandQuetch` | указанный файл |

Исходники: `bridge/GateUi.cs`, `GateMenu.cs`, `GateKeys.cs`, `GateClean.cs`,
`GateQMon.cs`. Компиляция — `csc.exe` из `C:\Windows\Microsoft.NET\Framework\v4.0.30319\`.

## Грабли агента очереди

Все три стоили времени — при правке агента не потерять:

1. **Сторож будит агента только при `*.sql` в очереди.** Условие в
   `bridge_watchdog.bat`: `if exist C:\GATE\_skud_queue\*.sql ...`. Одни `.cmd`
   задания не выполнятся никогда. Обход: класть рядом пустой `.sql`.
2. **Запуск `.cmd`-файла напрямую падает с `rc=1`.** Поэтому агент читает файл и
   выполняет **каждую строку отдельным** `cmd.exe /c <строка> >> <результат>`.
   Следствие: переменные (`set`/`%VAR%`), `if`, метки и `goto` не работают —
   только простые команды с абсолютными путями. `timeout` под перенаправленным
   вводом тоже не работает, вместо паузы — `ping -n N 127.0.0.1`.
3. **`File.Move` падает, если в `done\` уже есть файл с таким именем**, и
   обрывает всю очередь. Поэтому в агенте есть `SafeMove`: перед переносом
   назначение удаляется, а каждый файл обрабатывается под `On Error Resume Next`.

Порядок обработки: **сначала все `.sql`, потом все `.cmd`** — сбой на команде не
может помешать записи в базу.

## Как проверить, что всё живо

```sh
# очередь на сервере Gate (SMB)
smbclient '//192.168.2.160/C$' -U 'ALM\skudnew%<пароль>' -m SMB3 \
  -c 'cd GATE\_skud_queue; ls'

# служба приложения на LXC
ssh root@192.168.2.193 'systemctl is-active skud-gate'

# состояние пропусков
curl -s -b cookies 'http://192.168.2.193:8110/api/passes'

# залогинен ли оператор в Gate (окно доступа должно быть в списке)
# запустить GateUi.exe и посмотреть gate_ui.txt
```

Признаки проблемы:

| Что видно | Причина |
|---|---|
| двери из приложения не открываются | GateTerm не залогинен либо окно «Управление точками доступа» не открыто |
| задания лежат в очереди, `.result` не появляется | агент не запускается: в очереди нет `*.sql` либо завис на `File.Move` |
| `.result` есть, но в журнале проход без имени | у пользователя в Gate выставлен срок (`UseExpiry = 1`) |
| карта не открывает, в журнале «Неразрешенный ключ» | не было перезапуска GateServ или слот конфликтует |
| карта открывает после отзыва | **известная проблема:** ключ остался в контроллере, см. выше |
