- **Перерывы сотрудника:** в карточке блок «Перерывы» — обед/перекуры (начало, конец, название), сохраняются в таблице `breaks`. Часы в отчётах считаются за вычетом перерывов, попавших в интервал «приход–уход» (поле `break_min` в строках). API: `POST /api/employee-breaks`.
- **Вкладка «Сотрудники»:** список всех (поиск по ФИО/табельному/подразделению), колонка «График работы»; клик по строке открывает карточку, как и клик по ФИО в любом отчёте.
- **Личные графики работы:** в карточке сотрудника (клик по ФИО) можно задать «с … по …» и сохранить; хранится в таблице `schedules` (SQLite, ключ — `user_ptr`), при расчёте опозданий/ранних уходов берётся личный график, а для остальных — смена из отчёта. API: `POST /api/schedules`, график приходит в `/api/person`.
- **Табель, итоги по дням:** в печати под часами второй строкой идут минуты (заголовок «Итого по дням, ч/мин»).
- **Перекуры:** вкладка «Перекуры» — пары «вышел/вернулся» через выбранные точки (по умолчанию проходная производства), свод по людям и список последних выходов; галочка «Формировать отчёт» отключает расчёт. Печать и Excel. `gate.breaks_report()`.
- **Табель за месяц (для кадров):** фильтры — месяц, подразделение, сотрудник (список или все), **точки входа и точки выхода** (мультивыбор, каждая пара считается отдельно). Режимы: «обычный отчёт» (по выбранным точкам) и «первое — последнее предъявление за день» с началом новых суток (0–23 ч, для ночных смен). новая вкладка «Табель» — сетка сотрудники × дни месяца с часами `Ч:ММ`, итогом по человеку и по дням, выходные подсвечены. Печать (A4 landscape, `TIMESHEET_TEMPLATE`) и Excel. В API — `/api/timesheet?month=YYYY-MM`, печать — `/print/timesheet`, Excel — `/export/timesheet.xls`; данные строит `gate.timesheet()`.
- **История проходов догружена за 2026 год:** `gate.sync_events` залил 323 суточных журнала (с 01.01 по 19.11), в базе 1,52 млн событий. Раньше синхронизировались только последние 7 дней, поэтому за октябрь и ранее отчёты были пустые. Данные: `data/gate.sqlite` 110 МБ, `data/events` 190 МБ.

## Сделано 24.11 — план-факт, доступы, отсутствия

- **План-факт** (вкладка): план по личным графикам (рабочие дни минус отсутствия) против факта из проходов, отклонение, опоздания; печать. `gate.plan_fact()`.
- **Доступы** (вкладка): матрица «сотрудник × устройство» из `access_table`/`readers`, поиск, печать. `gate.access_rights()`.

- **Вкладка «КПП» (пост охраны):** выбор точек, живая лента проходов и всплывающая карточка сотрудника с фото на 4,5 секунды (настраивается) при проходе через выбранные точки. Фото показывается только в карточке сотрудника и на КПП (в списке — инициалы).
- **Табель Т-13:** кнопки «Т-13» и «Т-13 Excel» в табеле — форма по ОКУД 0301001 с кодами Я/В/О/Б/К/ПР/ДО/НН, часами по дням и итогами; служебные записи без проходов отбрасываются. `gate.t13()`, `/print/t13`, `/export/t13.xls`.
- **Фото сотрудника:** загрузка в карточке (JPG/PNG/WebP до 4 МБ), хранение в `data/photos`, отдача `/photo/<id>`; показывается в карточке и списке сотрудников. `POST /api/photo`, удаление — `{"remove":true}`.
- **Отсутствия**: в карточке сотрудника блок (отпуск/больничный/отгул/командировка/прогул) — исключаются из плана. Таблица `absences`, `POST /api/absences`.

## Веб-отчёты `reports/` — СКУД Gate-IP
Мониторинг и отчёты посещаемости: `server.py` (порт 8110 на LXC 192.168.2.193, вход `vitosamin`), `gate.py` (данные и SQL для Gate), `web/index.html`. Подробности — `reports/README.md`, механизм ключей — `reports/KEYS.md`.

**Вход в GateTerm — автоматический.** Отдельно заходить в Gate не нужно: мост поднимает терминал и логинится через `GateCtl.exe`; после ребута это происходит само (см. «Сделано 19.11»).

**Ключи карт — выдача работает, отзыв нет:**

- **выдать пропуск** — работает: карта открывает двери, проход в журнале с именем;
- **отозвать, удалить, истечение** — **не работает**: запись из базы уходит, а ключ остаётся в памяти контроллера, и карта продолжает пускать.

- Запись в `config.mdb` сама дверь **не** открывает: контроллер узнаёт ключ только после **перезапуска GateServ** — служба читает картотеку при старте. Поэтому после каждого пропуска приложение кладёт в очередь `zz_gateserv_restart.cmd`.
- Слот ключа (`AccessTable.InnerNum`) — **один на устройство**, а не на считыватель: память ключей у контроллера общая. Иначе ключ встаёт в занятый слот и контроллер отвечает «Нет доступа. Неразрешенный ключ».
- Строки доступа пишутся только на «считывателе доступа» (где уже есть картотека, обычно `Readers.Num = 1`).
- Срок в Gate **не выставляем** (`UseExpiry = 0`): у всех 288 сотрудников он пуст, а с заполненным сроком Gate не сопоставляет пользователя с событием — в журнале нет имени.

**Почему отзыв не работает:** служба пишет ключи только в **свободные** слоты, занятый не перезаписывает и не очищает. Проверено и не помогло: удаление записи, `Status = 1`, подмена значения карты, команда Gate «Передача ключей в контроллеры» (меню id=41). Проверять только картой у двери — по базе нельзя.

**19.11 проверено окончательно:** удаление человека **через саму картотеку Gate** меняет только `Users` и `AccessTable` — `CommandQuetch` остаётся пустым, `Keys` не меняется. Значит Gate тоже не посылает команду очистки, и «снять её из очереди» невозможно — план закрыт. Работает только «Очистка банков ключей» (меню 42), затем «Передача ключей» (41), в нерабочее время.

**Следующий шаг:** отзыв и истечение — только ночная очистка банков (меню 42 → 41), двери на это время карты не пускают. Инструменты разведки лежат в `bridge/` и `C:\Users\Public\` (`GateUi`, `GateMenu`, `GateKeys`, `GateClean`, `GateQMon`), описание — в `KEYS.md`.

**Грабли интерфейса Gate:** окна модальные по одному (второе не открыть — VB-ошибка); «ОК» в диалоге ошибки **завершает GateTerm**; после перезапуска нужен вход оператора (список операторов — таблица `Operators` в `config.mdb`).

**Грабли агента очереди** (`C:\Users\Public\skud_agent.vbs`, запуск из `bridge_watchdog.bat` раз в 2 минуты):

- сторож будит агента, только если в очереди есть `*.sql` — одни `.cmd` не разбудят;
- запуск `.cmd`-файла напрямую падает с `rc=1`, поэтому агент выполняет файл построчно через `cmd.exe /c <строка>` (переменные и `if` там не работают);
- `File.Move` падает, если в `done\` уже есть файл с таким именем, и обрывает всю очередь — перед переносом назначение удаляется.

Коммитить только свои пути, не `git add -A`.
